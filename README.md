# QueryForge ⚒️

A full-stack AI-powered web application that converts plain English questions/requests into SQL queries and executes them on a live MySQL database in real time.

---

## What it does

- Type a question/request in plain English
- The LLM generates the appropriate SQL query using live database schema
- The query executes on a MySQL database
- Results are displayed in a clean table

Supports SELECT, INSERT, and UPDATE queries.
DELETE and DROP are blocked for safety.

---

## Tech Stack

| Layer    | Technology                        |
|----------|-----------------------------------|
| Backend  | Python, FastAPI                   |
| AI / LLM | Groq API (llama-3.1-8b-instant)   |
| Database | MySQL                             |
| Frontend | HTML, CSS, JS                     |

---

## How it works

```
User question/request
↓
FastAPI receives the question/request
↓
database.py extracts live MySQL schema
↓
llm.py injects schema + question/request into Groq prompt
↓
LLM returns a SQL query
↓
Python executes the query on MySQL
↓
Result displayed as a table in the UI
```

## Setup and Installation

### Pre-requisites
- Python 3.10+
- MySQL Community Server
- Groq API key (free at https://console.groq.com)

### 1. Clone the repository

```bash
git clone https://github.com/krishgoel20/Text-to-SQL.git
cd Text-to-SQL
```

### 2. Set up the backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Configure environment variables

Create a `.env` file inside the `backend/` folder:

```
GROQ_API_KEY=your_groq_api_key_here
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_mysql_password
DB_NAME=ecommerce_db
```

### 4. Run the backend

```bash
uvicorn main:app --reload
```

The database is created and seeded automatically on startup.
No manual SQL setup required.

### 5. Open the frontend

```bash
cd ../frontend
python -m http.server 5500
```

Visit **http://localhost:5500** in your browser.

## Features

### 🤖 AI Features
- 🧠 **Natural language understanding** — a single Groq API call reads the user's plain English question and returns a valid, schema-aware SQL query ready for execution
- 📐 **Live schema injection** — the database schema is extracted at runtime and injected into every LLM prompt, ensuring the model only references tables and columns that actually exist
- 🛡️ **Safety guardrails** — DELETE and DROP statements are explicitly blocked at the prompt level, preventing accidental data loss regardless of what the user types
- ⚡ **Fast inference** — powered by Groq's LPU hardware for near-instant SQL generation with minimal latency

### 🗄️ Database Features
- 🌱 **Auto-seeding database** — the entire MySQL database (schema + data) is dropped and recreated automatically on every server start, no manual SQL setup required
- 🔍 **Schema-aware querying** — the app reads the live database structure at runtime, not hardcoded table names, making it adaptable to any schema
- ✏️ **Multi-operation support** — supports SELECT, INSERT, and UPDATE queries through natural language, covering read and write operations
- 🔗 **Relational data** — database includes foreign key relationships between customers, products, and orders tables, enabling JOIN-based queries

### 🖥️ Frontend & UX Features
- 💬 **Plain english input** — users type questions naturally with no SQL knowledge required, with Enter key support for quick querying
- 📋 **Generated SQL display** — every query shows the exact SQL generated by the LLM, making the system transparent and educational
- 📊 **Clean results table** — query results render in a structured dark-themed table with column headers and row count
- ✅ **Operation feedback** — INSERT and UPDATE queries display a clear success message with the number of rows affected instead of an empty table
- 🚨 **Error handling** — failed or invalid queries surface a clear error message in the UI instead of a silent crash

## Key Concepts Demonstrated

- **Prompt engineering** — live schema is injected into every LLM prompt so the model always generates schema-aware SQL.
- **Schema-aware querying** — the app reads the actual database structure at runtime, not hardcoded table names.
- **Database seeding** — entire database builds itself from Python code on every server start, no manual setup needed.
- **Full-stack integration** — FastAPI backend, MySQL database, and vanilla JS frontend working together.
- **Safety guardrails** — DELETE and DROP statements are blocked at the prompt level.

---

## Limitations

- Same question/request may produce different SQL queries on different runs due to LLM non-determinism.
- No query history stored between sessions.
- Not deployed (runs locally only).
